# Ecossistema tecnológico

[← Apresentação da Amz Labs](../profile/README.md) · [Soluções de engenharia](./services.md)

**A arquitetura começa pelos requisitos do cliente.** Combinamos soluções comerciais, SaaS e open source considerando integração, segurança, custo total, suporte e capacidade de operação do time.

## Plataformas de referência

Os nomes abaixo orientam conversas de arquitetura e integração. O escopo de implementação e sustentação é definido após avaliação técnica.

| Categoria | Tecnologias de referência |
| :--- | :--- |
| Cloud e infraestrutura | AWS, Microsoft Azure, Oracle Cloud Infrastructure. |
| Observabilidade comercial e SaaS | Datadog, Dynatrace, Grafana Cloud, New Relic. |
| Open source e cloud native | Kubernetes, OpenTelemetry, Prometheus, Grafana OSS, Loki, Tempo, OpenSearch, Argo CD. |
| Infraestrutura e entrega | Terraform, Pulumi, Ansible, GitHub Actions, GitLab CI, Azure DevOps. |
| IA e automação | APIs de IA, modelos de linguagem, serviços gerenciados e ferramentas open source, conforme a arquitetura. |

## Tecnologia, serviço e parceria

- **Referência tecnológica:** plataforma considerada, estudada ou integrada no desenho de uma solução. Sua presença aqui não indica certificação ou experiência comprovada em todos os cenários.
- **Serviço contratado:** implementação, integração ou sustentação com capacidade técnica, entregáveis e responsabilidades validados para o projeto.
- **Parceria formal:** vínculo comercial com um fabricante, divulgado somente quando formalizado e autorizado. A lista acima não representa credenciamento, parceria ou revenda autorizada.

## Princípios de integração

Preferimos interfaces documentadas, padrões interoperáveis e automações rastreáveis. Observabilidade, segurança e confiabilidade entram desde a arquitetura. A escolha entre SaaS e open source considera também quem vai operar a solução e como ela poderá evoluir.
